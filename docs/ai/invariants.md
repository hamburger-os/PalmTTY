# PalmTTY architecture invariants

These constraints are intentional. A task that needs to break one must explicitly update architecture/security documentation and explain the trade-off.

1. **Shell access is high trust.** PalmTTY is equivalent to remote access as the Agent OS user.
2. **Browser lifetime is not terminal lifetime.** Browser disconnect must not terminate a running PTY.
3. **Agent lifetime is not terminal lifetime.** Each live terminal is owned by an independent Session Worker and must survive restart or replacement of the HTTP/API Agent. This does not imply persistence across OS reboot, logoff, or Worker termination.
4. **The Session Worker owns canonical terminal state.** PTY ownership, headless xterm state, terminal geometry, output sequence, replay history and exited-session retention live in the Worker. The Agent is a replaceable control plane and must not recreate a competing canonical terminal state. Browser recovery must synchronize geometry before restoring/replaying state; a geometry change requires a canonical snapshot rather than replaying output produced for the previous geometry. Explicit retained-session deletion is also Worker-owned cleanup: the Agent may request retirement after the Session is terminal, but must not delete canonical terminal/recovery state behind a live Worker's back.
5. **Recovery is authenticated local IPC.** Agent↔Worker control uses a per-session high-entropy secret. The secret never reaches the browser and must not appear in argv, URLs, normal logs or terminal environment. Persisted PIDs are metadata, never authority to kill a process. IPC failure alone is not proof that a Worker is dead; recovery capability is Worker-owned state.
6. **Durability begins at authenticated adoption.** A newly spawned Worker is provisional even after READY; it becomes an independent durable Session only after the creator authenticates and sends `adopt`. An unadopted Worker must self-clean its PTY and recovery state after a short creation lease.
7. **All buffers are bounded.** Replay history, WebSocket payloads, Worker IPC frames, terminal dimensions, session counts, slow-client queues, Workspace text previews/complete-file exports/image previews, Git history/detail/diff responses and Session attachment count/file/aggregate bytes need explicit limits.
8. **Workspace authority stays explicit and layered.** Authenticated, exact-Origin Web requests may create/edit/delete persistent Workspace definitions. Workspace root authority is name/cwd/bounded environment; Terminal launch authority is nested under `workspace.terminal` (runtime + optional startupCommand); Remote App launch authority is a bounded saved profile set. Session creation/restart never accepts ad-hoc runtime/environment overrides. Directory browsing, terminal-profile discovery and Remote App executable discovery are bounded inspection surfaces, not general file-read/command APIs. Remote App browsing exposes directories + `.exe` entries only. Workspace Files stays read-only and confined by canonical/symlink containment; Git resolves the repository containing Workspace cwd, keeps reads bounded and disables unintended repository code execution where possible, and exposes only fixed typed writes behind state/snapshot/trust checks. Session image attachments remain Session-scoped private runtime files. Launch targets are validated on Workspace mutation and again before their respective Worker bootstrap. Workspace environment values may be sensitive local configuration but are not a secret-vault feature.
9. **Authentication and Origin are separate controls.** A browser terminal connection requires both. Origin never replaces authentication. Network exposure is selected through one explicit profile: `local` stays loopback; `lan` is authenticated but unencrypted private/overlay HTTP, rejects non-private client source addresses, and uses exact auto-detected private Origins; `reverseProxy` and direct `https` accept only explicit HTTPS Origins and derive Secure-cookie behavior. Low-level bind/origin/cookie escape booleans must not reappear.
10. **No secrets in URLs.** Login secrets/tokens and Worker capabilities must not be query parameters.
11. **No terminal or attachment content in default logs.** Input, output, AI prompts, uploaded image bytes, access tokens, Worker secrets and workspace environment values are sensitive.
12. **No silent elevation or console-dependent autostart.** Agent autostart, Workers and PTYs stay in the intended normal-user security context; PalmTTY does not silently install LocalSystem/root services or change host linger/elevation policy. The Windows scheduled task launches a GUI-subsystem PalmTTY host directly; PowerShell may compile that host during install but is not a long-lived supervisor.
13. **The terminal and attachment core are AI-vendor-neutral.** Codex, Claude Code, Antigravity, OpenCode or other CLI agents remain workloads, not core protocol dependencies. Attachment APIs expose bounded local files/paths; they do not encode a vendor-specific multimodal message protocol.
14. **Documentation is part of done.** Behavior-changing work must run the docs-sync workflow and keep all four layers consistent.
15. **Mobile viewport geometry has one browser-side owner.** The Session workbench owns the current VisualViewport frame at every zoom level, plus safe-area and virtual-keyboard/browser-chrome presentation geometry. `visualViewport.scale` must never disable framing; user pinch zoom remains browser-owned and must not be disabled or forcibly reset. TerminalView derives usable rows/columns only from its mount ResizeObserver/FitAddon path and must not add a competing VisualViewport listener. Editable controls on coarse-pointer/mobile layouts stay at 16px or larger to avoid browser focus zoom.
16. **xterm remains the browser keyboard/composition authority.** PalmTTY may compensate for confirmed browser/xterm IME gaps only through a narrow public-API adapter around xterm's helper textarea/key handler/input/paste/mode APIs. It must not create a second general input editor, duplicate genuine composition commits, infer a CLI from terminal content, or send a second parallel PTY input protocol. Long-text paste preserves xterm bracketed-paste semantics, and virtual cursor keys honor the terminal's current application-cursor mode.
17. **Remote Apps are not terminal Sessions.** Remote App lifecycle, native capture/input state, WebRTC media and recovery authority belong to a separate AppWorker protocol/runtime generation. They must not be tunneled through the terminal WebSocket or added to Terminal Worker canonical state. Sharing a generic framed-local-IPC utility does not merge the protocols.
18. **Remote App launch authority is persisted Workspace configuration, independent of Terminal runtime.** The browser may start only a saved Remote App profile by workspace ID + profile ID. A create/signaling request must never accept a one-off executable, argv, environment override, PID, HWND or capture target. Profiles persist only id/name/typed Win32-or-MSIX launch identity/argv; capture FPS/width/height are not profile authority. A Workspace may use WSL for Terminal/Git/Files while Remote Apps still launch as current-user Windows host applications. Known-app detection and executable browsing must remain bounded discovery surfaces.
19. **Remote App capture/input authority is the PalmTTY-owned App Job, never the desktop.** A native helper may capture/control only a visible top-level window whose PID still belongs to the PalmTTY-owned Job Object. For packaged apps it must activate an installed current-user AUMID, verify a fresh (non-reused) process PID and exact package family, then require successful Job assignment; activation alone grants no window authority. Capture failure must not fall back to monitor/full-desktop capture. Input must revalidate ownership, stay typed/bounded, and must not bypass Windows UIPI/UAC or introduce an elevation path.
20. **Remote App channels are capability-minimal and bounded.** Video is a bounded WebRTC media track and control is a bounded typed DataChannel. Server-to-browser cursor telemetry must contain only current verified Job-owned-window-relative coordinates or hidden, never global desktop positions or cursor images. Remote App mobile Keyboard is only a UI adapter to the existing bounded Unicode text and allowlisted typed-key controls: it must not duplicate or prematurely send IME composition, create a second PTY path, add arbitrary input commands, or broaden native authority. Typed native input-status feedback can report foreground/UIPI refusal without new authority; send at bounded rates and drop on peer backpressure. Display-size hints may adapt capture presentation only within protocol/native hard bounds and must not select a capture target. ICE/STUN/TURN configuration is bounded host configuration returned only through authenticated capability discovery; it does not create a PalmTTY cloud-relay trust boundary. Clipboard, audio, microphone, camera, file drag/drop, arbitrary key/input commands, whole-desktop capture and additional peers are absent unless separately designed with explicit authority, resource limits, privacy rules and documentation. Agent loss must not terminate an adopted AppWorker; AppWorker/control-pipe loss must not leave a PalmTTY-launched app tree unmanaged.
