# PalmTTY architecture invariants

These constraints are intentional. A task that needs to break one must explicitly update architecture/security documentation and explain the trade-off.

1. **Shell access is high trust.** PalmTTY is equivalent to remote access as the Agent OS user.
2. **Browser lifetime is not terminal lifetime.** Browser disconnect must not terminate a running PTY.
3. **Agent lifetime is not terminal lifetime.** Each live terminal is owned by an independent Session Worker and must survive restart or replacement of the HTTP/API Agent. This does not imply persistence across OS reboot, logoff, or Worker termination.
4. **The Session Worker owns canonical terminal state.** PTY ownership, headless xterm state, terminal geometry, output sequence, replay history and exited-session retention live in the Worker. The Agent is a replaceable control plane and must not recreate a competing canonical terminal state. Browser recovery must synchronize geometry before restoring/replaying state; a geometry change requires a canonical snapshot rather than replaying output produced for the previous geometry. Explicit retained-session deletion is also Worker-owned cleanup: the Agent may request retirement after the Session is terminal, but must not delete canonical terminal/recovery state behind a live Worker's back.
5. **Recovery is authenticated local IPC.** Agent↔Worker control uses a per-session high-entropy secret. The secret never reaches the browser and must not appear in argv, URLs, normal logs or terminal environment. Persisted PIDs are metadata, never authority to kill a process. IPC failure alone is not proof that a Worker is dead; recovery capability is Worker-owned state.
6. **Durability begins at authenticated adoption.** A newly spawned Worker is provisional even after READY; it becomes an independent durable Session only after the creator authenticates and sends `adopt`. An unadopted Worker must self-clean its PTY and recovery state after a short creation lease.
7. **All buffers are bounded.** Replay history, WebSocket payloads, Worker IPC frames, terminal dimensions, session counts, slow-client queues, Workspace text previews/complete-file exports/image previews, Git history/detail/diff responses and Session attachment count/file/aggregate bytes need explicit limits.
8. **Workspace authority stays explicit and layered.** Authenticated, exact-Origin Web requests may create/edit/delete persistent Workspace definitions. Workspace root authority is name/cwd/bounded environment; Terminal launch authority is nested under `workspace.terminal` (runtime + optional startupCommand). Session creation/restart never accepts ad-hoc runtime/environment overrides. Directory browsing and terminal-profile discovery are bounded inspection surfaces, not general file-read/command APIs. Workspace Files stays read-only and confined by canonical/symlink containment; Git resolves the repository containing Workspace cwd, keeps reads bounded and disables unintended repository code execution where possible, and exposes only fixed typed writes behind state/snapshot/trust checks. Session image attachments remain Session-scoped private runtime files. Launch targets are validated on Workspace mutation and again before their respective Worker bootstrap. Workspace environment values may be sensitive local configuration but are not a secret-vault feature.
9. **Authentication and Origin are separate controls.** A browser terminal connection requires both. Origin never replaces authentication. Network exposure is selected through one explicit profile: `local` stays loopback; `lan` is authenticated but unencrypted private/overlay HTTP, rejects non-private client source addresses, and uses exact auto-detected private Origins; `reverseProxy` and direct `https` accept only explicit HTTPS Origins and derive Secure-cookie behavior. Low-level bind/origin/cookie escape booleans must not reappear.
10. **No PalmTTY secrets in URLs.** PalmTTY login/bootstrap tokens and Worker capabilities never enter URLs. Third-party process bootstrap credentials never enter catalogue/rendered link URLs, persistent files, logs or PalmTTY cookies. A separate explicit authenticated exact-Origin action may hand an owned managed instance to its configured independent Origin (HTTPS, or the derived private-gateway LAN HTTP Harness route); remote browsers never receive loopback token URLs. This operator-approved upstream handoff does not establish shared authentication.
11. **No terminal or attachment content in default logs.** Input, output, AI prompts, uploaded image bytes, access tokens, Worker secrets and workspace environment values are sensitive.
12. **No silent elevation or console-dependent autostart.** Agent autostart, Workers and PTYs stay in the intended normal-user security context; PalmTTY does not silently install LocalSystem/root services or change host linger/elevation policy. The Windows scheduled task launches a GUI-subsystem PalmTTY host directly; PowerShell may compile that host during install but is not a long-lived supervisor.
13. **The terminal and attachment core are AI-vendor-neutral.** Codex, Claude Code, Antigravity, OpenCode or other CLI agents remain workloads, not core protocol dependencies. Attachment APIs expose bounded local files/paths; they do not encode a vendor-specific multimodal message protocol.
14. **Documentation is part of done.** Behavior-changing work must run the docs-sync workflow and keep all four layers consistent.
15. **Mobile viewport geometry has one browser-side owner.** The Session workbench owns the current VisualViewport frame at every zoom level, plus safe-area and virtual-keyboard/browser-chrome presentation geometry. `visualViewport.scale` must never disable framing; user pinch zoom remains browser-owned and must not be disabled or forcibly reset. TerminalView derives usable rows/columns only from its mount ResizeObserver/FitAddon path and must not add a competing VisualViewport listener. Editable controls on coarse-pointer/mobile layouts stay at 16px or larger to avoid browser focus zoom.
16. **xterm remains the browser keyboard/composition authority.** PalmTTY may compensate for confirmed browser/xterm IME gaps only through a narrow public-API adapter around xterm's helper textarea/key handler/input/paste/mode APIs. It must not create a second general input editor, duplicate genuine composition commits, infer a CLI from terminal content, or send a second parallel PTY input protocol. Long-text paste preserves xterm bracketed-paste semantics, and virtual cursor keys honor the terminal's current application-cursor mode.


17. **Single terminal controller.** The Agent grants one ephemeral input/resize lease per attached Session, not one per browser tab. Additional authenticated sockets are observers; they cannot input or resize, cannot take control while the owner is attached, and recover from canonical Worker geometry. Agent loss drops leases but not PTY. Browser WS wire version is `palmtty.v4`.
18. **Sensitive reader progress.** The read-only speech reader may retain a hashed file identifier, sampled content signature and paragraph index in browser localStorage, but never persist novel prose or pass it to implicit remote speech services. Chapter navigation and visible DOM remain bounded.

19. **Speech is opt-in, scoped and never terminal authority.** Browser Web Speech localService=true is the only auto-selected voice; false or absent localService requires explicit per-voice per-reading consent, with no silent remote fallback. Optional Qwen3-TTS is an authenticated bounded Agent-to-loopback capability with a separate host-managed model process and secret; it cannot read workspace paths, launch arbitrary models, mutate Files, or enter the Terminal Worker protocol. Model/audio/text are never logged or written into the Workspace by default.

20. **External web applications remain independent.** Official VS Code Web and Harness use independent page navigation, distinct Origins and authentication, separate from PalmTTY Workspace/Terminal state. Harness Desktop/Web may share upstream DSH_HOME history through separate profiles; upstream cross-process single-writer ownership must never be bypassed. Windows uses the official installed Desktop public CLI, not a private duplicate or private GUI backend. The explicit single-user LAN IP gateway treats these applications as one trusted host: cookies are not port-isolated. The proxy strips the PalmTTY session cookie upstream; this is not a claim of hostname-level isolation. Application embedding, same-Origin proxying and shared PalmTTY credentials are not supported. LAN PalmTTY and managed Harness may use HTTP through the explicit private deployment profile; Code uses trusted HTTPS for secure-context-dependent features. Managed/external ownership is explicit in one host configuration. Application binaries remain operator-installed; personal managed launch is opt-in and never bypasses authentication or license acceptance. Codex remains a generic terminal workload; no Remote App/RDP/Azure Tunnel subsystem.

21. **Node runtime single source.** `.node-version` pins the exact Node 24 CI/release baseline, root `engines.node` constrains supported versions to the same minimum within Node 24, and `@types/node` matches that major. Windows/Linux native PTY releases must use the same ABI. No Node 22 compatibility branches.

22. **Managed ownership is separate from durable terminals.** Only applications/installers created by this Agent belong to its process containers; no adopting unknown port owners or saved PIDs. Lease loss/close reclaims app descendants while independent Session Workers survive Agent replacement. Windows app Jobs disallow breakaway; the autostart Agent Job retains Worker breakaway. Each public application root is a distinct Origin; managed IP roots derive only from the gateway address and ports, with no private DNS or duplicated managed URL configuration; explicit authenticated authorization is the only remote upstream-token surface.
