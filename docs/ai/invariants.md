# PalmTTY architecture invariants

These constraints are intentional. A task that needs to break one must explicitly update architecture/security documentation and explain the trade-off.

1. **Shell access is high trust.** PalmTTY is equivalent to remote access as the Agent OS user.
2. **Browser lifetime is not terminal lifetime.** Browser disconnect must not terminate a running PTY.
3. **Agent lifetime is not terminal lifetime.** Each live terminal is owned by an independent Session Worker and must survive restart or replacement of the HTTP/API Agent. This does not imply persistence across OS reboot, logoff, or Worker termination.
4. **The Session Worker owns canonical terminal state.** PTY ownership, headless xterm state, terminal geometry, output sequence, replay history and exited-session retention live in the Worker. The Agent is a replaceable control plane and must not recreate a competing canonical terminal state. Browser recovery must synchronize geometry before restoring/replaying state; a geometry change requires a canonical snapshot rather than replaying output produced for the previous geometry. Explicit retained-session deletion is also Worker-owned cleanup: the Agent may request retirement after the Session is terminal, but must not delete canonical terminal/recovery state behind a live Worker's back.
5. **Recovery is authenticated local IPC.** Agent↔Worker control uses a per-session high-entropy secret. The secret never reaches the browser and must not appear in argv, URLs, normal logs or terminal environment. Persisted PIDs are metadata, never authority to kill a process. IPC failure alone is not proof that a Worker is dead; recovery capability is Worker-owned state.
6. **Durability begins at authenticated adoption.** A newly spawned Worker is provisional even after READY; it becomes an independent durable Session only after the creator authenticates and sends `adopt`. An unadopted Worker must self-clean its PTY and recovery state after a short creation lease.
7. **All buffers are bounded.** Replay history, WebSocket payloads, Worker IPC frames, terminal dimensions, session counts and slow-client queues need explicit limits.
8. **Workspace authority stays explicit.** Authenticated, exact-Origin Web requests may create/edit/delete persistent workspace definitions, including cwd/runtime/shell, bounded workspace environment variables, and startup command. The directory picker and terminal-profile discovery API are bounded runtime-inspection surfaces; profile discovery may enumerate known Host shells and registered WSL distributions but must not start arbitrary commands or expose file contents. The Session workbench uses separate bounded Workspace tools rather than terminal-WebSocket command tunneling: file listing/preview remains read-only and confined to the persisted Workspace root after canonical/symlink containment checks, while Git resolves the repository containing the persisted Workspace cwd and explicitly reports repository scope. Git reads use porcelain-v2 status plus bounded diff/history/branch queries with external diff/textconv/fsmonitor execution and log signature-helper execution disabled; working-tree diff also resolves the selected path's `filter` attribute and neutralizes that driver's clean/process commands and `required` flag so viewing a diff does not execute repository-configured content filters. Git writes are a fixed typed operation set (stage/unstage/restore/commit/branch/stash and non-interactive fetch/pull/push), never arbitrary argv. Every write requires an expected repository state token and explicit repository-code-execution acknowledgement; incomplete/truncated status is never valid write authority; writes are serialized by resolved repository rather than Workspace ID; destructive restore also verifies the exact loaded diff snapshot. PalmTTY disables Git hooks and interactive credential/editor prompts, but normal Git filters may still execute for trusted-repository operations and the UI must disclose that boundary. Helper subprocesses must not inherit PalmTTY authentication secrets. Session creation and restart never accept ad-hoc runtime/environment overrides: they resolve the persisted workspace by ID. Workspace launch targets are validated on mutation and again before Worker bootstrap. Workspace environment values are persisted local configuration, may be sensitive, and are not a secret-vault feature.
9. **Authentication and Origin are separate controls.** A browser terminal connection requires both. Origin never replaces authentication. Network exposure is selected through one explicit profile: `local` stays loopback; `lan` is authenticated but unencrypted private/overlay HTTP, rejects non-private client source addresses, and uses exact auto-detected private Origins; `reverseProxy` and direct `https` accept only explicit HTTPS Origins and derive Secure-cookie behavior. Low-level bind/origin/cookie escape booleans must not reappear.
10. **No secrets in URLs.** Login secrets/tokens and Worker capabilities must not be query parameters.
11. **No terminal content in default logs.** Input, output, AI prompts, access tokens, Worker secrets and workspace environment values are sensitive.
12. **No silent elevation or console-dependent autostart.** Agent autostart, Workers and PTYs stay in the intended normal-user security context; PalmTTY does not silently install LocalSystem/root services or change host linger/elevation policy. The Windows scheduled task launches a GUI-subsystem PalmTTY host directly; PowerShell may compile that host during install but is not a long-lived supervisor.
13. **The terminal core is AI-vendor-neutral.** Codex, Claude Code, OpenCode or other CLI agents remain workloads, not core protocol dependencies.
14. **Documentation is part of done.** Behavior-changing work must run the docs-sync workflow and keep all four layers consistent.
